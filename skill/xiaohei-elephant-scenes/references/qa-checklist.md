# 小黑象 2.0 QA Checklist

## Entrypoint

- [ ] `agents/openai.yaml` 不是 `{}` 空对象。
- [ ] `agents/openai.yaml` 的 `default_prompt` 明确调用 `$xiaohei-elephant-scenes`，而不是旧版 `$xiaohei-scenes`。
- [ ] `agents/openai.yaml` 明确要求读取 `xiaohei-elephant-ip-lock.md`、`style-dna.md`、`prompt-template.md`、`object-patterns.md`、`qa-checklist.md` 和 `GOTCHAS.md`。
- [ ] `agents/openai.yaml` 明确要求读取 `cover-typography-runtime-contract.md`，并要求创建 `cover-typography-receipt.md`。
- [ ] 路由边界清楚：2.0 / 真实物品 / 物理动作 / 小现场走本 Skill；普通白底手绘走 `xiaohei-elephant-illustrations`；旧版 `xiaohei-scenes` 不承接“小黑象”请求。

## Critical

- [ ] 小黑象有短象鼻、小耳朵、短腿、白点眼。
- [ ] 小黑象是四足小象：4 条短圆桩腿贴在身体下方，允许遮挡但不能只剩两条人形腿。
- [ ] 小黑象不是小黑人、黑色人形、火柴人、旧小黑或普通黑球。
- [ ] 小黑象不是厚重 3D 玩偶、写实小象、萌宠、公仔或商品模型。
- [ ] 小黑象看起来轻巧、有动作弹性，不是笨重圆胖摆件。
- [ ] 小黑象自身占比足够小：标准图高度约 3%-5% 画面高；黑色视觉体量约为此前测试图的 1/3；不得超过主物品高度的 1/3。
- [ ] 标准图 Prompt 前 8 行已使用 `scale-calibration.md` 的尺度补偿锁：模型目标 1.5%—2.5%、主物品至少 6 倍高；若首张超标，`qa.md` 已记录 A/B/C 档位，而非重复同一 Prompt。
- [ ] 同一文章有 2 张及以上图片时，已建立 `prompts/xiaohei-character-lock.md`，并记录唯一母版绝对路径和各模式尺度基准。
- [ ] 画面有真实物品，不是纯手绘解释图。
- [ ] 小黑象正在承担核心物理动作。
- [ ] 一张图表达一个段落级核心结论或冲突，并能看出主旨、处境/输入、机制/动作、结果/边界中的至少 3 层；不是只摘一个主题名词。
- [ ] 没有虚构未确认的人名、品牌、数据、经历和案例。
- [ ] 如果主题明确涉及真实品牌 / 产品 / App，画面使用真实官方 logo / app icon / 产品标识；如果品牌不明确，则没有乱编伪 logo。
- [ ] 品牌 logo 只是识别锚点，没有抢走小黑象、核心动作和真实物品隐喻，也没有暗示官方合作、授权或背书。

## Article Batch Consistency

- [ ] 第 1 张已单独通过 IP、四足、尺度和动作 QA，才被冻结为本文章唯一角色母版。
- [ ] 后续每张都在 `referenced_image_paths` 中直接使用同一张母版；没有用上一张成图串联生成下一张。
- [ ] 参照图只锁定小黑象形体、比例、材质和尺度；没有误复制母版背景、道具或构图。
- [ ] 同一画幅模式中，每张小黑象高度相对母版的偏差不超过 ±10%，并且仍在该模式的绝对占比范围内。
- [ ] 每张已与母版并排检查：头身、耳鼻、四足、白点眼、哑光材质和黑色体量没有明显漂移。
- [ ] 未通过批次 QA 的图已重生；没有用后期缩放、裁切或拼贴修正角色大小。

## Standard

- [ ] 背景纯白或接近纯白，留白充足。
- [ ] 真实物品少而准：1 个主物品加 1-3 个有明确语义职责的辅助物件，最多 4 个视觉单元；每个物件都对应段落里的信息节点。
- [ ] 物件之间有清晰的阶段、因果、对比、组成、层级、筛选或闭环关系，并由一个主物理动作串联；不是孤立物件排队。
- [ ] 主物品没有大到像商品图。
- [ ] 整体场景占比中等偏轻，不是 close-up、商品摄影、玩具棚拍或品牌 KV。
- [ ] 镜头有明显后退感，画面四周保留大块白色呼吸区，不是近距离角色/物品特写。
- [ ] 彩色点缀面积小，没有大面积彩色便签堆、彩色抽屉标签或彩色纸片铺满画面。
- [ ] 中文标签像批注，贴近动作或物品，不像左右两侧的大标题。
- [ ] 中文标签 3-5 个，短且可读；分别贴近主旨、机制、结果、边界或关系，不写成长句。
- [ ] 画面不像 PPT、UI 截图、架构图或商业海报。
- [ ] 3 秒内能看懂核心动作。
- [ ] 真实品牌 logo 如果出现，必须贴在具体物品上，例如卡片、文件夹、设备屏幕、app tile、终端 tile 或工具盒；不要漂浮在空中当装饰。

## Failed Signals

- 小黑象只是站在旁边。
- 小黑象看起来像黑色玩具小象、萌宠小象或商品模型。
- 小黑象太圆、太大、腿太粗短，显得笨重不灵巧。
- 小黑象占比过大，像主视觉主体或吉祥物；高度超过画面高 6%，或黑色体量没有比之前测试明显缩小。
- 同一文章多图中小黑象忽大忽小、忽胖忽瘦，或头身、耳鼻、四足比例明显不同。
- 小黑象只有两条腿、腿像人腿/火柴腿、有膝盖脚掌鞋子，或像小黑角色加了一根象鼻。
- 真实物品太多，动作不清楚。
- 画面只表达主题名词，没有输入/处境、机制和结果的完整关系。
- 辅助物件无法对应段落中的事实、阶段、角色、结果或边界，像装饰性道具堆。
- 画面有多个孤立物件，但没有一条主路径、接触关系、闸门或前后对照来解释它们的关系。
- 主题明确是飞书、Codex、OpenAI 等真实产品，但画面用了泛化图标或伪 logo，导致工具识别不准。
- logo 过大、漂浮、错误、山寨化，或让画面像品牌广告。
- 中文文字变成长标题。
- 标签过大、太远，像海报标题而不是现场批注。
- 角色或主物件太大，压住留白。
- 镜头太靠前，角色和物品像贴着观众脸。
- 彩色纸片、便签、抽屉标签过多，颜色抢过主动作。
- 背景出现灰底、暗角、渐变或厚重棚拍阴影。
- 角色没有象鼻。
- 角色没有四足小象结构。
- 画面像旧版小黑人场景图。
- 需要解释很多才懂，或缩略图里只能看出“主题是什么”，看不出“它是怎么发生、结果是什么”。

## Cover Mode

- [ ] Cover 是 21:9 超横版，不混入正文 16:9 配图数量。
- [ ] Cover prompt 已明确填写封面主题、主标题、标题重点词、底部金句、具体图解内容、真实主物品、小黑象动作和 3 秒读懂句；没有空变量。
- [ ] 背景符合深色科技感、青橙对比、弱 HUD / 玻璃拟态 / 发光连接线方向。
- [ ] 黑色小黑象没有压在黑色背景里；必须有浅色台面、纸面、聚光区或清晰边缘光，1 秒内能看清轮廓、短象鼻和四足。
- [ ] Cover 小黑象高度约 4%-6% 画面高，黑色视觉体量约为此前测试 cover 的 1/3；它只是执行动作的小角色，不是主视觉主体。
- [ ] 主标题位于标题区顶部居中，是第一视觉中心；使用中文粗体大号手绘字，不是白色细黑体或标准科技黑体。
- [ ] 主标题的字形仍是 ZCOOL KuaiLe 的圆润、轻松、略不规则手写气质；没有标准科技黑体、几何尖角字、网页/UI 字体或白字发光漂移。
- [ ] 背景、真实物品、小黑象、主标题、重点词、底部金句和短标签由同一次生图生成，没有本地叠字、后贴文字层、白色标题卡或独立文本框。
- [ ] `generation_passes` 为 1；没有生成 `title-overlay-zcool.png`、透明文字 PNG、`*-base.*`、`*text-layer*`、`*composite*` 或 `*merged*` 等中间产物，也没有把它们作为输入。
- [ ] 标题与场景共享纸张纹理、光影、透视、边缘质感和手绘装饰，能看出是同一张图的一部分，不像文字压在照片上。
- [ ] 线条和主文字为黑色，1-2 个重点词使用珊瑚红 `#E8655A`，辅助短标签使用暖灰 `#6B6B6B` 小字；深色底图有暖白纸张标题区或等价浅色承载面。
- [ ] 画面只有少量小星星、下划线、小箭头或勾选标记等手绘涂鸦，并保留充足留白，没有装饰堆叠。
- [ ] 底部金句只有一句，短、锋利、有观点，字号明显小于主标题，没有抢焦点。
- [ ] 具体图解真实出现在画面中，形成“起点物件/困境 -> 小黑象动作 -> 结果/转折”的可见物理链路，最多 3 个连续状态。
- [ ] 核心隐喻 3 秒内可读，例如“稿件 -> 小黑象推过验收门 -> 进入通过托盘”；不得只靠抽象发光面板表达。
- [ ] 主标题区、具体图解区、底部金句区有清晰层次，不像正文节点墙。
- [ ] 上方没有失控的大面积空白；标题、图解和物件形成连续视觉动线，不是“上面空、下面摆一排道具”。
- [ ] 小黑象仍满足四足、短象鼻、小耳朵、白点眼，不因深色科技风漂移成人形角色。
- [ ] Allowed text 白名单已限定为主标题、可选副标题、底部金句和必要短标签；画面没有乱码、伪文字、多余英文或可读 HUD 小字。
- [ ] 已创建 `cover-typography-receipt.md`，记录字体路径、字体 SHA-256、排版参考图、image_gen 输入、最终图、Allowed text、QA 后端和证据路径。
- [ ] `status: PASS` 仅在 `visual_qa: PASS` 且字体哈希匹配时使用；视觉 QA 不可用、400、429、超时或任何解析错误时，回执为 `BLOCKED`，没有发送正式封面。
