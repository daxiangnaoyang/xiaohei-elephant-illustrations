## QA 分级与通道

- [ ] 标准 16:9 正文图先通过 shot record 的段落语义/密度门，再由 Codex 当前 GPT 系列运行时做一次原生视觉 QA；该通道只检查 IP 形体、角色尺度和文字白名单。
- [ ] 运行于 Hermes/智谱外部 API 时，才使用 `scripts/qa_image.py` 这个 Zhipu/GLM 适配器；不得把它的模型名写成 Codex 默认视觉模型。
- [ ] `qa_image.py` 的 `--allowed-text` 或 `--allowed-text-file` 已填写本图允许出现的全部可读文字；没有文字时明确传空白名单，额外文字仍判定失败。
- [ ] Hermes 外部通道的 `qa_image.py` 返回 `PASS` 才能交付；返回 `FAIL` 必须重生，返回 `BLOCKED`（缺 key、接口报错、429、超时或返回不可解析）不得把候选图当正式图。Codex 原生视觉 QA 不可用时同样只能 `BLOCKED`。
- [ ] `qa_image.py` 不替代 3 秒读图检查：画面仍必须表达 shot record 的输入/处境、机制/动作和结果/边界，且密度档位与段落复杂度匹配。
- [ ] Cover、3:4 小红书、9:16 和长卷不使用轻量通道替代全量清单；Cover 仍执行 typography contract、字体回执和输入血缘检查，3:4 小红书执行独立运行时契约和卡片回执。

## Critical

- [ ] 小黑象有短象鼻、小耳朵、短腿、白点眼。
- [ ] 小黑象是四足小象：4 条短圆桩腿贴在身体下方，允许遮挡但不能只剩两条人形腿。
- [ ] 小黑象不是小黑人、黑色人形、火柴人、旧小黑或普通黑球。
- [ ] 小黑象不是厚重 3D 玩偶、写实小象、萌宠、公仔或商品模型。
- [ ] 小黑象看起来轻巧、有动作弹性，不是笨重圆胖摆件。
- [ ] 小黑象自身占比足够小：标准图高度约 3%-5% 画面高；黑色视觉体量约为此前测试图的 1/3；标准真实物品模式不得超过主物品高度的 1/3，扇面内容分支不得超过平面内容画布高度的 1/3。
- [ ] 标准图 Prompt 前 8 行已使用 `scale-calibration.md` 的尺度补偿锁：模型目标 1.5%—2.5%、主物品至少 6 倍高；若首张超标，`qa.md` 已记录 A/B/C 档位，而非重复同一 Prompt。
- [ ] 同一文章有 2 张及以上图片时，已建立 `prompts/xiaohei-character-lock.md`，并记录唯一母版绝对路径和各模式尺度基准。
- [ ] 标准真实物品模式有真实物品；扇面内容分支有平面内容画布，不生成实体折扇。
- [ ] 标准真实物品模式的小黑象正在承担核心物理动作；扇面内容分支的小黑象与标题、气泡、图标或下划线有清晰平面关系。
- [ ] Shot list 已完整记录原始段落、段落类型、独立信息节点、必须看见的节点及其视觉承载方式，并明确选择 D1 / D2 / D3；不是只摘一个主题名词。
- [ ] 密度档位与段落复杂度匹配：D1 仅用于单一判断；解释型段落默认至少 D2；含多步骤、多条件、多角色、对比转折、分支或明确边界的段落使用 D3。
- [ ] 成图覆盖当前档位规定的核心节点：D1 为 2-3 个、D2 为 3-4 个、D3 为 4-6 个；每个节点可由物件、状态、动作、位置、关系线或短标签承载，不能把机制和结果全部压成一个主题物件。
- [ ] 没有虚构未确认的人名、品牌、数据、经历和案例。
- [ ] 如果主题明确涉及真实品牌 / 产品 / App，画面使用真实官方 logo / app icon / 产品标识；如果品牌不明确，则没有乱编伪 logo。
- [ ] 品牌 logo 只是识别锚点，没有抢走小黑象、核心动作和真实物品隐喻，也没有暗示官方合作、授权或背书。
- [ ] 扇面内容分支中已显式选择一个品牌锚点：小黑象或官方大象 logo；没有同时出现，也没有留空。红色印章默认是内容装饰，不冒充品牌 logo。

## Standard

- [ ] 背景纯白或接近纯白，留白充足。
- [ ] 真实物品按密度档位变化而不是固定超简：D1 为 1 主 + 1 辅助，D2 为 1 主 + 2-3 辅助，D3 为 1 主/紧凑主组 + 3-5 辅助物件或状态单元；每个单元都对应段落节点。
- [ ] 物件之间有清晰的阶段、因果、对比、组成、层级、筛选或闭环关系，并由一个主物理动作链串联；D3 可有一个分支或前后转折，但不是孤立物件排队。
- [ ] 主物品没有大到像商品图。
- [ ] 整体场景占比中等偏轻，不是 close-up、商品摄影、玩具棚拍或品牌 KV。
- [ ] 镜头有明显后退感，画面四周保留大块白色呼吸区，不是近距离角色/物品特写。
- [ ] 彩色点缀面积小，没有大面积彩色便签堆、彩色抽屉标签或彩色纸片铺满画面。
- [ ] 中文标签像批注，贴近动作或物品，不像左右两侧的大标题。
- [ ] 中文标签按密度档位控制：D1 为 2-3 个、D2 为 4-5 个、D3 为 5-7 个；短且可读，分别贴近主旨、机制、结果、边界或关系，不写成长句。
- [ ] 画面不像 PPT、UI 截图、架构图或商业海报。
- [ ] 3 秒内能看懂核心动作。
- [ ] 真实品牌 logo 如果出现，必须贴在具体物品上，例如卡片、文件夹、设备屏幕、app tile、终端 tile 或工具盒；不要漂浮在空中当装饰。

## Failed Signals

- 小黑象只是站在旁边。
- 小黑象看起来像黑色玩具小象、萌宠小象或商品模型。
- 小黑象太圆、太大、腿太粗短，显得笨重不灵巧。
- 小黑象占比过大，像主视觉主体或吉祥物；高度超过画面高 6%，或黑色体量没有比之前测试明显缩小。
- 同一文章多图中小黑象忽大忽小、忽胖忽瘦，或头身、耳鼻、四足比例明显不同。
- 小黑象只有两条腿、腿像人腿/火柴腿、有膝盖脚掌鞋子，或像小黑角色加了一根象鼻。
- 真实物品太多，动作不清楚。
- 画面只表达主题名词，没有输入/处境、机制和结果的完整关系。
- 解释型段落被压成 D1，画面只有一个主题物件和一个动作，缺少中间机制、条件或结果。
- 段落里明明有多个步骤、角色、条件或转折，却仍沿用所有图片相同的“主物品 + 一个点缀”密度。
- Shot list 列出了多个独立信息节点，但成图只把它们写进标签，没有对应的物件状态、空间层次、动作或关系。
- 辅助物件无法对应段落中的事实、阶段、角色、结果或边界，像装饰性道具堆。
- 画面有多个孤立物件，但没有一条主路径、接触关系、闸门或前后对照来解释它们的关系。
- 主题明确是飞书、Codex、OpenAI 等真实产品，但画面用了泛化图标或伪 logo，导致工具识别不准。
- logo 过大、漂浮、错误、山寨化，或让画面像品牌广告。
- 中文文字变成长标题。
- 标签过大、太远，像海报标题而不是现场批注。
- 角色或主物件太大，压住留白。
- 镜头太靠前，角色和物品像贴着观众脸。
- 彩色纸片、便签、抽屉标签过多，颜色抢过主动作。
- 背景出现灰底、暗角、渐变或厚重棚拍阴影。
- 角色没有象鼻。
- 角色没有四足小象结构。
- 画面像旧版小黑人场景图。
- 需要解释很多才懂，或缩略图里只能看出“主题是什么”，看不出“它是怎么发生、结果是什么”。
