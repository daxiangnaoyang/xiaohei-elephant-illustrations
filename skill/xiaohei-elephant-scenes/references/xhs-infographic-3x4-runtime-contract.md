# 3:4 小红书手绘信息图运行时契约

## 模式身份

本契约只适用于明确提出“**小黑象 + 小红书图文 / 3:4 信息图 / 小红书卡片**”的请求。它是 `xiaohei-elephant-scenes` 的独立 2.0 分支，不改变标准 16:9 真实物品场景、21:9 Cover 或 9:16 视频封面的默认规则。

这是一张单页内容卡，不是实体折扇、不是摄影场景、不是 1.0 白底手绘解释图，也不是多页拼图。它把完整段落编译成一张有主判断、信息节点和关系线的手绘教育信息图，并保留扇面母版的内容设计语言。

## 路由边界

- 用户明确说“小红书 / XHS / 3:4 / 图文卡片 / 知识卡片”且同时要求小黑象时，进入本分支。
- 用户只说“手绘信息图”而未点名小黑象，走 `handdrawn-infographic-card`，不强行引入小黑象 IP。
- 用户说“9:16 视频封面 / 扇面内容封面”，继续走 `prompt-template.md` 的 9:16 Fan-Surface 分支，不切换成 3:4。
- 用户说“白底手绘 / 低科技手绘隐喻 / 1.0”，走 `xiaohei-elephant-illustrations`，不使用本分支。

## 视觉不变量

### 画布与纸面

- 比例固定为 `3:4` 竖版；一张卡片一次生图，不生成联系表、九宫格、多页合成图或轮播拼图。
- 背景固定为暖奶油纸张肌理 `#F5F0E8` 或近似浅色纸面。禁止灰黑、深褐、炭色底、暗黑科技背景、彩色渐变和大面积晕染背景。
- “扇面”只作为平面内容设计语言：允许轻微不规则纸面边缘、轻微放射式排布、蓝绿低饱和边缘泼墨和中央单一主题刷痕；禁止实体扇子、扇片、扇骨、扇柄、折痕、手持关系或可辨识的扇形实体轮廓。

### 手绘信息图语法

- 线条和形状带轻微手绘 wobble；主文字和线条为墨黑，辅助标注为暖灰 `#6B6B6B`。
- 信息区可以使用浅蓝 `#A8D8EA`、薄荷绿 `#B5E5CF`、薰衣草紫 `#D5C6E0`、浅桃 `#F4C7AB`，但只服务信息分区，不铺满画布。
- 主强调色只保留一个，优先珊瑚红 `#E8655A`；它用于标题重点词、中央刷痕、关键关系或印记，不同时铺多种高饱和色。
- 允许 2-4 个不规则手绘气泡、2-4 个与文稿直接相关的简笔图标、1-2 个朱红色手绘印章/印记和少量箭头、下划线、圈选。它们必须解释文稿关系，不是随机贴纸墙。
- 版面可以使用 2-4 个手绘区域或圆角色块承载节点，但不能变成 UI、仪表盘、复杂流程图或高密度 PPT 卡片墙。

### 信息密度

- 先读完整段落，再选择一个版面主视觉语法：流程、因果、对比、问题到解决、组成、层级或反馈。
- 每张卡片至少表达“处境/问题 -> 机制/判断 -> 结果/边界”中的 3 个关键节点；复杂段落最多 6 个可见节点。
- 每个节点必须由图形、状态、位置、关系线、气泡或短标签承载；不能只摘主题名词，也不能靠长文字补全机制。
- 标题只给一个核心判断；辅助文字只保留 2-6 字短标签或短批注；正文不直接搬上图。
- 3:4 缩略图必须在 3 秒内读出“主题判断 + 一个关系线索 + 小黑象品牌锚点”。

### 小黑象与品牌

- 使用完整 `references/xiaohei-elephant-ip-lock.md`。小黑象是极小的平面黑色执行者：短象鼻、小圆耳、白点眼、四足短圆桩腿、低矮轻巧身体。
- 小黑象高度约为画面高 `3%-5%`，不超过主内容画布高度的四分之一；不得成为吉祥物主角。优先让象鼻指向标题重点、牵住关系线、压住下划线或盖住一个确认印记。
- 品牌锚点只能选一个：默认小黑象；只有用户明确选择并提供可核验官方资产时，才使用官方大象 logo。二者不能同时出现。
- 用户明确点名飞书、Codex、OpenAI 等真实产品时，只有对应真实物件或文稿节点需要品牌识别，才使用准确官方 logo；logo 必须小、贴在具体物件或信息单元上，不漂浮、不伪造、不做广告 KV。

## 生成与重试

- 所有文字、纸面、刷痕、气泡、图标、印记、小黑象和品牌锚点必须在同一次 `image_gen` 中融入；禁止本地叠字、独立文字层、标题卡、透明 PNG、合成图或后期修字。
- 每个候选只调用一次 `image_gen`。单张卡片最多 8 个完整候选；第 8 版仍未满足 P0 文字/安全区/品牌或 IP 门槛时，标记 `NEEDS_HUMAN`，不生成第 9 版。
- 多张小红书卡片逐张生成，禁止把多张卡片交给一次生图。第一张通过 IP 与尺度 QA 后冻结角色母版；后续最多 3 个独立 job 并行引用同一不可变母版。
- 图片、最终 Prompt 和本契约回执统一归档到 `/Users/dx/Hermes-agent/21-配图空间/<文章或项目名>/`。

## QA 顺序

按以下顺序验收，任一 P0 失败都不交付：

1. 画幅、暖纸背景和上下平台安全区。
2. 文字白名单逐字核对，禁止错字、漏字、多余伪文字。
3. 小黑象 IP、四足结构、尺度和唯一品牌锚点。
4. 扇面语言是否保留但没有实体折扇。
5. 段落节点、关系线和 3 秒缩略图可读性。
6. 手绘质感、颜色克制和装饰数量。

视觉理解默认使用 Codex 当前 GPT 系列运行时；不能调用视觉 QA 时标记 `BLOCKED` / `未验证`，不得把候选图当正式图。Hermes/智谱的 `scripts/qa_image.py` 只检查它支持的轻量字段，不能替代本分支的完整视觉 QA。
