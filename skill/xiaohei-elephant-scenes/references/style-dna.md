# 小黑象 2.0 视觉 DNA

## 核心公式

```text
小黑象 + 真实主物品 + 段落信息节点分层 + 物理动作链 + 短中文标签 + 留白叙事
```

## 标准模式

- 16:9 横版正文配图
- 纯白或接近纯白摄影棚背景
- 一个真实主物品小现场，按段落复杂度选择 D1 / D2 / D3 信息预算；不是每张都用同一种超简构图
- D1 仅用于真正单一判断；D2 是解释型段落默认档；D3 用于多步骤、多条件、多角色、对比转折或明确结果/边界的段落
- 小黑象参与核心物理动作
- D1 / D2 / D3 分别使用 2-3 / 4-5 / 5-7 个中文手写短标签
- 少量蓝 / 黄 / 红 / 橙点缀
- 留白充足，轻、怪、清爽

## 段落级信息密度

小黑象 2.0 正文图不是把文章主题画成一个单独物件，而是先理解完整段落，再把段落中的独立信息节点编译成一张可读的视觉摘要。生成前必须先写清：

- 一句话主旨：这一段最终想让读者理解什么。
- 段落类型：单一判断、因果机制、流程步骤、对比转折、组成层级、决策筛选、反馈闭环或案例复盘。
- 处境 / 输入：读者正在面对的卡点、起始状态或问题。
- 独立信息节点：输入、机制、角色、阶段、条件、证据、结果和边界中，哪些不能互相替代。
- 结果 / 边界：动作完成后发生什么，或这一段给出的判断与限制。

### 信息密度分档

| 档位 | 适用段落 | 可见预算 | 使用原则 |
| --- | --- | --- | --- |
| D1 轻量 | 只有一个独立判断、一个条件和一个动作/状态变化 | 1 主物品 + 1 辅助物件；2-3 个标签；2-3 个节点 | 例外档，不得因为追求留白而滥用 |
| D2 解释型 | 普通观点解释，包含处境、1-2 个机制和结果/边界 | 1 主物品 + 2-3 个辅助物件；4-5 个标签；3-4 个节点 | 默认档，正文多数段落应从这里开始判断 |
| D3 综合型 | 因果链、3+ 步骤/元素、多角色/条件、对比转折、决策分支、反馈或明确边界 | 1 主物品/紧凑主物品组 + 3-5 个辅助物件或状态单元；5-7 个标签；4-6 个节点 | 用一个连贯的真实物品小现场承载，不做卡片网格 |

段落中出现多个独立动词，或“因为/所以/但是/如果/同时/最终/第一/第二/否则”等因果、转折、条件、步骤信号时，至少从 D2 开始；有 4 个以上不能合并的信息节点时使用 D3。密度档位是内容判断，不是装饰偏好。

每个必须看见的节点都要有视觉承载方式：真实物件、物件状态、空间位置、物理动作、接触关系、路径/闸门或短标签。不能把“机制 + 条件 + 结果”合并成一个泛化物件，也不能只靠读者回看正文补全画面。

优先使用一条物理链、前后对照、嵌套/堆叠、闸门/筛选或弧形闭环来组织信息。D3 可以使用前景/中景/后景的层次，或在主路径上增加一个分支/前后转折；但仍然只保留一个主视觉语法，不做节点墙、仪表盘、复杂流程图或 PPT 卡片。

信息密度来自“段落节点覆盖 + 层级 + 关系 + 可见结果”，不来自无语义道具、更大文字、颜色堆叠或把所有名词逐个画出来。画面仍需保持摄影棚留白和真实物品的轻质感；信息增加时扩展真实物品小现场，不靠拉近镜头或放大小黑象。

## 原版小黑 2.0 质感锁定

小黑象 2.0 要继承原版 `xiaohei-scenes` 的“白色空间里的真实物件小现场”，不是把小黑象做成 3D 吉祥物棚拍。生成时先锁以下不变量：

- **镜头后退一档**：标准 16:9 图里，整体场景仍像站在白色展台前远看一个小现场，而不是贴近拍角色和物件。D1 场景覆盖约 46%-58% 画面宽度、26%-38% 高度；D2 可扩展到约 50%-64% 宽度、28%-40% 高度；D3 可扩展到约 56%-70% 宽度、32%-48% 高度。扩展真实物品小现场，不靠 close-up、低机位或放大小黑象。
- **主物品少而准，密度按段落变化**：D1 保留 1 个主物品 + 1 个辅助物件；D2 保留 1 个主物品 + 2-3 个辅助物件；D3 保留 1 个主物品/紧凑主物品组 + 3-5 个辅助物件或状态单元。每个单元都要对应段落节点，不要把便签、文件夹、卡片铺满画面，也不要让辅助物件彼此孤立。
- **角色占比压低**：旧版 `xiaohei-scenes` 的小黑高度通常是画面高的 8%-13%，但它是细胳膊细腿的小黑影，黑色视觉面积很小。小黑象是低矮实体剪影，同样高度会显得重三倍。2.0 标准图必须把小黑象高度压到画面高的 3%-5%，黑色视觉体量约为此前测试图的 1/3，且不超过主物品高度的 1/3。
- **角色轻巧化**：小黑象应像“黑色哑光小剪影/软胶小执行者 + 极简白点眼”，身体小、短、轻，四肢可动，动作敏捷。不能像厚重 3D 玩具、儿童玩偶、真实动物模型、圆胖摆件或吉祥物公仔。
- **象腿锁定**：小黑象必须是四足小象。腿是 4 条短小圆桩腿，贴在身体下方，前后腿可被身体遮挡但不能只剩两条人形细腿。禁止二足站姿、火柴腿、人类小黑腿、膝盖/脚掌/鞋感、长条身体接两根腿。
- **动作优先于摆拍**：小黑象必须在推、拉、挡、托、盖章、检查、筛选、拧紧、搬运、修补等核心动作里发力；不能只是站在物品旁边合影。
- **标签像批注，不像标题**：中文文字应贴近物品、动作、阶段或关系；D1 / D2 / D3 分别控制在 2-3 / 4-5 / 5-7 条，像手写批注、下划线和小箭头。标签要命名信息节点，不要左右两侧放大标题，不要写完整观点句。
- **颜色只做节奏点**：彩色面积要小，通常 4-6 个小点缀即可。大面积彩色便签、彩色抽屉标签和彩色纸堆会显廉价。
- **阴影极轻**：只允许物件脚下有轻接触阴影；不要明显灰底、暗角、渐变、厚重棚拍阴影。
- **拒绝笨重感**：小黑象不应像笨重雕塑压在画面里。它要像正在认真干活的小执行者，能钻、推、拉、够、递、扛一点点东西，有轻微前倾或拉伸姿态。
- **文章批次锁**：同一篇文章的多张图先冻结一张已验收角色母版，后续每张直接引用母版。形体、头身、耳鼻、四足和材质不变；同一画幅模式的高度相对母版偏差不超过 ±10%。场景、物件、动作和朝向可变，不能用改变角色胖瘦来服务构图。

## Cover 模式

Cover 版是单独的一张图，不和正文 16:9 小现场混用。参考 `../wechat-tech-cover-image` 的科技感封面要求，但把小黑象 2.0 融进去：

- **比例**：21:9 超横版，适合公众号头图/封面。
- **背景**：深色科技背景，青橙对比，弱 HUD 网格、轻微纸感、玻璃拟态卡片和发光连接线。
- **主体**：一个小黑象 2.0 真实物品隐喻作为主视觉；小黑象仍然必须四足、短象鼻、小耳朵、白点眼。
- **角色占比**：Cover 里小黑象也不能成为巨型主角。小黑象高度约 4%-6% 画面高，黑色视觉体量约为此前测试 cover 的 1/3；主视觉应由“真实主物品 + 物理链路”承担，小黑象只是执行动作的小角色。
- **内容完整性**：Cover prompt 必须同时写明封面主题、主标题、标题重点词、底部金句、具体图解内容、真实主物品、小黑象动作和 3 秒读懂句。用户没给标题或金句时，先生成再填写，不得把空变量交给图像模型。
- **构图**：主标题区、具体图解区、底部金句区分开；主体不要压满画面，保留科技留白和清晰视觉焦点。
- **主题字体**：主标题是第一视觉中心，在标题区顶部居中，使用中文粗体大号手绘字（bold, large, hand-drawn lettering）。线条与主文字黑色；1-2 个重点词使用珊瑚红 `#E8655A`；辅助短标签使用暖灰 `#6B6B6B` 小字，每条 2-5 词。深色底图要增加暖白纸张标题区或等价浅色承载面，不能改用白色细黑体绕开规范。
- **手绘装饰**：使用少量小星星、下划线、小箭头或勾选标记作为涂鸦点缀；保持充足留白、干净构图，装饰不能抢标题或图解。
- **底部金句**：只保留一句，短、锋利、有观点；用户原句优先，没有则根据主题自动生成。字号明显小于主标题，不得成为第二标题。
- **具体图解**：必须把主题翻译成“起点物件/困境状态 -> 小黑象用短象鼻执行核心动作 -> 结果物件/转折状态”的可见物理链路，最多 3 个连续状态。不能只画抽象科技氛围或漂浮面板。
- **文字策略**：主标题、重点词、金句、图解、小黑象和真实物品必须同一次生成、一体成型。可用本地字体生成本次标题参考图并作为 `image_gen` 的视觉参考，但禁止生成无文字底图后再叠字、贴白色标题卡或覆盖独立文字层。文字不稳时压缩标题、减少文字白名单、强化 prompt 后重生成。
- **融合标准**：标题必须与背景共享纸张纹理、光影、透视和涂鸦语言，并与具体图解形成视觉动线；不能悬浮在大面积空白上，也不能像 PPT 文本框压在摄影场景前面。
- **品牌标识**：当主题明确涉及真实品牌、产品或 App 时，真实物品可以带官方品牌 logo / app icon / 产品标识，例如飞书场景用飞书标识，Codex / OpenAI 场景用 OpenAI 标识。logo 是识别锚点，不是广告主视觉。
- **反风格**：不要正文信息图式密集节点，不要营销海报大字压满，不要无依据的伪品牌 logo、错误 logo 或 logo 抢主角，不要伪文字 HUD。

### 9:16 视频封面分支

- 继承 21:9 Cover 的深色科技、青橙对比、纸张纹理、真实物品隐喻和 one-pass 文字规则，但必须独立重排为手机竖版，不直接裁切横版。
- 竖版采用“标题 -> 中部物理动作 -> 金句”的单列阅读路径：顶部 0%-12%、底部 84%-100% 留给平台 UI；标题 14%-32%；主视觉 34%-72%；金句 75%-83%。
- 主视觉优先上下或斜向组织，最多一个真实主物品或紧凑物品组；不横向铺开，不把多个道具排成一行。
- 标题最多两行，优先在手机缩略图上保证 3 秒可读；标题和金句都要与同一块纸面、光线或物理动线融合，不生成播放按钮、字幕条或平台控件。
- 9:16 里的小黑象仍是 4%-6% 画面高的小执行者，不因窄画幅被放大成吉祥物；短象鼻必须接触真实物品并构成动作缺口。

## 小黑象硬门槛

必须同时满足：

- 黑色实心小象
- 短象鼻
- 小耳朵
- 四足短圆桩腿
- 白点眼
- 非人形、非火柴人、非旧小黑

## 真实物品原则

真实物品要有摄影质感、自然光影和透视，但不能厚重。优先选择能承载动作的物品：

- 印章、放大镜、闸门、透明盒、玻璃罩
- 闹钟、钥匙、绳子、滑轮、拉杆、按钮
- 文件夹、卡片、便签、夹子、收纳盒
- 漏斗、筛子、水管、胶带、工具箱
- 积木、轨道、桥、门、货架、抽屉

如果主题明确点名真实平台或产品，主物品可以是带真实品牌标识的 app 卡片、文件夹、设备屏幕、终端 tile、文档卡、工具盒或产品包装元素。标识必须服务“这是什么工具 / 平台”的识别，不要做成品牌海报。

真实物品的“真实”来自材质、透视、接触阴影和可触碰感，不来自数量、复杂度或棚拍厚度。判断标准：

- 一眼能看清主物品是什么。
- 一眼能看清小黑象对它做了什么。
- 去掉中文标签后，仍能大致读出冲突。
- 物件之间有空气，画面不是素材拼贴。
- 画面必须覆盖当前密度档位规定的全部核心节点，并能看出至少一条“输入/处境 -> 机制/动作 -> 输出/结果”的关系；只剩主题物件、把解释型段落压成 D1，或看不出中间机制与结果，信息密度不合格。

## 反风格

不要：

- 旧版小黑 / 小黑人 / 黑色人形
- 厚重 3D 玩偶小象 / 写实小象 / 萌宠小象 / 儿童玩具公仔
- 笨重圆胖小象 / 大头大身子摆件 / 近距离角色特写
- 小黑象高度超过画面高 6% / 黑色体量过大 / 比主物品还抢眼
- 二足站立小象 / 两根人形腿 / 火柴腿 / 鞋子脚掌 / 长条身体接腿
- UI 截图 / App 截图 / 仪表盘
- PPT 信息图 / 卡片网格 / 节点墙 / 复杂流程图 / 架构图
- 商业海报 / 科技 HUD / 赛博大屏
- 无依据的伪品牌 logo / 错误 logo / logo 抢主角 / 暗示官方背书
- 大量文字 / 长标题 / 密集标签 / 只画主题名词而不表达机制和结果
- 没有关系的物品排队 / 物品堆满画面
- 写实动物、萌宠、儿童卡通
- 角色或主物品占据画面过大，像商品摄影或品牌 KV
