# 小黑象 2.0 真实物品场景图

## 核心契约

小黑象 2.0 不是“主题名词配一个物件”，而是把**一个完整段落**压缩成一张可读的视觉摘要：

```text
完整段落 -> 主旨/处境/节点 -> 密度档位 -> 真实物品关系 -> 小黑象物理动作 -> 短标签 -> QA
```

统一公式：

```text
小黑象 + 真实物品 + 段落信息节点分层 + 物理动作链 + 短中文标签 + 留白叙事
```

共同不变量：

- 一张正文图表达一个段落级核心结论，但必须让输入/处境、机制/动作和结果/边界中的关键节点可见。
- 真实物品服务于段落隐喻；每个物件、状态或标签都必须有语义职责，不能靠装饰补密度。
- 小黑象是唯一角色，必须是短象鼻、小圆耳、白点眼、四足短圆桩腿的轻巧黑色小象；禁止二足、人形腿、火柴腿、鞋脚、玩具化和厚重摆件感。
- 用户明确点名飞书、Codex、OpenAI 等真实产品时，相关真实物品可以使用对应官方 logo / app icon；logo 必须准确、很小、贴在具体物品上，不漂浮、不伪造、不做品牌广告。未点名或无法确认时使用中性图标。
- Codex 的编排和默认视觉理解使用当前 GPT 系列运行时；`glm-4.6v` 只属于 Hermes/智谱外部 API 适配器，不得写成 Codex 的视觉模型。
- 密度增加时扩展真实物品小现场的层次和关系，不放大小黑象，不拉近镜头，不把画面做成卡片网格、节点墙、UI、仪表盘或 PPT。
- 没有完整段落时，不补造机制、结果、品牌、数据或案例；将缺失内容写成“未获取”，只输出待补充 shot list 或 prompt。

## 主流程

### 1. 先选模式

- **标准正文图**：16:9；默认入口；一个段落级真实物品小现场。
- **Cover**：21:9；单独一张，不计入正文配图数量；标题、核心隐喻和金句一次成型。
- **9:16 视频封面**：重新设计竖向构图，不裁切或拉伸 21:9；输入为已确认文稿时，默认采用扇面内容视觉分支。
- **彩蛋长卷**：约 2.6:1—3:1；用真实物品和曲线路径表达项目复盘、个人经历或产品演化。

用户未明确说“封面 / cover / 9:16 / 视频封面 / 长卷 / 彩蛋”时，默认标准正文图。

### 2. 编译完整段落

先读文章真实段落或小节正文，再填写一张 shot record。不要只从标题或主题词推断画面：

```text
主题：
原始段落 / 小节正文：
段落主旨 / 一句话结论：
读者处境 / 输入问题：
段落类型：单一判断 / 因果机制 / 流程步骤 / 对比转折 / 组成层级 / 决策筛选 / 反馈闭环 / 案例复盘
独立信息节点：输入、机制、角色、阶段、条件、证据、结果、边界中哪些不能合并
必须看见的节点及承载方式：物件 / 状态 / 位置 / 动作 / 接触关系 / 路径 / 短标签
结果 / 判断 / 边界：
视觉关系：流程 / 因果 / 对比 / 组成 / 层级 / 闭环 / 决策门
可见信息链：输入/处境 -> 机制/小黑象动作 -> 输出/结果/边界
真实主物品：
辅助物品或状态单元及语义职责：
核心物理动作：
小黑象动作：
密度档位及选择依据：D1 / D2 / D3
中文短标签：
画面 3 秒读懂句：
风险 / 避坑：
```

规则：

- 每个不可合并的节点必须有可见承载；标签只能命名节点，不能代替机制、条件或结果。
- 先确定物理关系，再选择物品。优先使用一条物理链、前后对照、嵌套/堆叠、闸门/筛选或弧形闭环。
- 一个画面只保留一条主视觉语法和一条主动作链。D3 允许一个分支或前后转折，但不能把物件横向排队。
- 小黑象用短象鼻完成推、拉、挡、托、检查、修补、盖章、搬运、拧紧、拉绳或守门等动作；不添加人类手臂和手掌。

### 3. 按段落选择密度

密度是内容判断，不是装饰偏好。以 `references/style-dna.md` 为最终细则，主入口只保留这张决策表：

| 档位 | 何时使用 | 真实物品 / 状态单元 | 标签 | 可见节点 |
| --- | --- | --- | --- | --- |
| **D1 轻量** | 只有一个独立判断、一个主要条件和一个动作/状态变化 | 1 主 + 1 辅助 | 2-3 个 | 2-3 个 |
| **D2 解释型** | 普通解释段落，包含处境、1-2 个机制和结果/边界 | 1 主 + 2-3 辅助 | 4-5 个 | 3-4 个 |
| **D3 综合型** | 因果链、3+ 步骤/元素、多角色/条件、对比、分支、反馈或明确边界 | 1 主/紧凑主组 + 3-5 辅助或状态单元 | 5-7 个 | 4-6 个 |

D1 是例外，不是默认。段落出现多个独立动词或“因为/所以/但是/如果/同时/最终/第一/第二/否则”等逻辑信号时，至少从 D2 开始；有 4 个以上不可合并节点时使用 D3。复杂度上升时扩展真实物品小现场，不增加文字、色块或角色体量。

### 4. 用唯一模板生成

标准图和所有封面都使用 `references/prompt-template.md` 的对应模板，不另写平行 Prompt。

标准 16:9 必须：

- 在最终英文 Prompt 前 8 行放 `SCALE IS THE FIRST PRIORITY` 尺度补偿块：角色生成目标 1.5%—2.5% 画面高、主物品至少是角色 6 倍高，并按 D1/D2/D3 调整小现场；实际验收仍为 3%—5%。超标按 `scale-calibration.md` 的 B/C 档重写构图并重生。
- 折入完整 `Xiaohei Elephant 2.0 IP lock`，尤其是短象鼻、小耳朵、四足短圆桩腿、白点眼和禁止二足/人形腿。
- 按密度档位填入真实主物品、辅助物件/状态单元、每个单元的语义职责、核心动作、关系链和 2-3 / 4-5 / 5-7 个短标签。信息密度不能只写在 shot list 里，必须落到画面结构。
- 保持近白摄影棚、远镜头、轻接触阴影和大块留白。小黑象只是小执行者；信息增加时放大或展开真实物品现场，不放大角色。

同一文章有 2 张及以上同模式正文图时：先生成第 1 张并通过 QA，冻结为唯一角色母版；母版冻结是唯一批次 barrier。之后 02/03/04 等剩余图片互相独立，默认并行启动最多 3 个 `codex exec`，每个 worker 只引用同一张不可变母版，并写入独立图片、Prompt 和 QA 结果；禁止用上一张替代母版或共享文件互相覆盖。遇到 API 限流时只降低并发或排队该 worker，不把默认流程退回全串行。具体字段用 `templates/article-character-lock.md`。

### 5. 运行时与输出

- 用户只要方案或 shot list 时不直接生图；用户明确要求生成时，Codex 有内置 `image_gen` 就按批次扇出独立 job。优先当前 GPT 系列运行时（具体模型以本机 `/Users/dx/.codex/config.toml` 的 `model` 为准），母版冻结后每个 job 只喂同一张已验收角色母版；标准图 QA 在 Codex 走 GPT 原生视觉理解，只有 Hermes/智谱外部通道才运行 `scripts/qa_image.py`。没有图像工具时只交付 prompt 和 QA，不声称已生成图片。
- 图片、prompt、母版锁和回执统一归档到 `/Users/dx/Hermes-agent/21-配图空间/<文章或项目名>/`；2.0 文章推送字段复用 `xiaohei-elephant-illustrations/references/unified-push-structure.md`，图片模式写明“2.0 真实物品场景图”。
- Cover 必须执行下一节的运行时门禁；生成后先 QA，首张不过不得批量继续。Cover 候选最多尝试 8 版，具体优先级和熔断见 `cover-typography-runtime-contract.md`。

## 分支硬门禁

### Cover 21:9

- 这是独立封面，不是正文图裁切；参考 `../wechat-tech-cover-image` 的深色科技感、青橙对比、弱 HUD/玻璃拟态和发光连接线，但必须有一个具体真实物品冲突。
- 生图前补齐：封面主题、主标题、1-2 个重点词、底部金句、起点物件/困境、小黑象核心动作、结果/转折、3 秒读懂句和 Allowed text 白名单。标题或金句缺失时先补写，不能传空变量。
- 主标题是第一视觉中心；小黑象高度约 4%—6% 画面高，只是执行者。深色背景必须给小黑象和真实物品一个暖白台面、纸面或清晰轮廓光，不能黑底黑象。
- 背景、物件、小黑象、标题、重点词、金句和必要标签由同一次 `image_gen` 生成。排版参考图只能作为 `TYPOGRAPHY_REFERENCE_ONLY` 输入，不能作为图层；禁止 `title-overlay-zcool.png`、透明文字 PNG、`*-base.*`、`*text-layer*`、`*composite*`、`*merged*`。
- 执行 `PREPARE -> GENERATE_ONCE -> VISUAL_QA_PASS -> DELIVER`。单个候选只允许一次 `image_gen`；整个 Cover 最多 8 个候选。只有 `cover-typography-receipt.md` 为 `status: PASS`、`generation_passes: 1`、`visual_qa: PASS` 且字体哈希匹配时才交付；视觉 QA 不可用、400、429、超时或余额不足均为 `BLOCKED`。达到 8 版仍未收敛时停止并标记 `NEEDS_HUMAN`，不盲目生成第 9 版。


### 9:16 视频封面与扇面内容

- 9:16 必须重新设计：顶部 0%—12%、底部 84%—100% 留给平台安全区；标题在 14%—32%，主视觉在 34%—72%，金句在 75%—83%。禁止裁切、拉伸、黑边和平台 UI。
- 扇面内容分支只生成一块平面内容画布，不生成实体折扇、扇片、扇骨、扇柄、折痕、手持、普通扇子图标或户外背景。
- 从已确认文稿生成主标题、金句、2-4 个批注气泡、2-4 个相关简笔图标和 1-2 个红色印章/印记；这些元素必须承载文稿信息，不得复制参考图原题字、印章或具体文案。
- 只使用一张登记的 `STYLE_REFERENCE_ONLY` 母版；品牌锚点只能选一个，默认是小黑象。只有用户明确选择并提供可核验官方资产时，才改用官方大象 logo；二者不能同时出现。
- 扇面分支同样执行 Cover 的一次生图、字体回执和 QA 门禁，详细变量以 `prompt-template.md` 为准。

### 彩蛋长卷

- 画幅约 2.6:1—3:1；用一条手绘曲线路径串联 5-8 个真实物品节点，左侧为起点，右侧为当前结论或下一阶段。
- 节点不编号、不做时间轴或 PPT 模块；每个节点都必须来自用户提供或可确认的事实，并有小黑象动作和短标签。

## QA 与交付

生成后按 `references/qa-checklist.md` 检查。标准正文图先执行 shot record 的段落语义/密度门，再由 Codex 当前 GPT 系列运行时做一次 IP、尺度和文字白名单快速视觉 QA；运行于 Hermes/智谱外部通道时，才使用 `scripts/qa_image.py` 这一 GLM 适配器。该脚本不检查 Cover 排版，也不能替代 3 秒读图门。Cover、9:16 和长卷仍执行对应的全量清单。以下任一项失败都不交付：

- 角色缺少短象鼻、小耳朵、白点眼或四足短圆桩腿，出现二足、人形腿、火柴腿、鞋脚、玩具化或厚重圆胖感。
- 标准图小黑象超过 3%—5% 画面高、Cover 超过 4%—6%，或镜头 close-up、低机位、主物品像商品图；不能靠后期缩放修正。
- 标准图没有真实物品、核心物理动作或完整的输入/机制/结果关系；解释型段落被压成 D1；辅助单元无法对应独立信息节点。
- 物件孤立排队、道具无语义、标签替代画面结构，或画面变成 PPT、UI、节点墙、复杂信息图、商业海报。
- 真实品牌未点名却被猜测，或 logo 错误、漂浮、过大、山寨化、抢主视觉。
- Cover 缺主题、标题、金句、具体图解或 Allowed text；文字像后贴、字体漂移、出现禁用中间产物或回执不是 PASS。
- Cover 重试超过 8 个候选仍未通过，或“断行/行数”和平台安全区冲突时没有按 P0 安全区、P1 可读性与内容、P2 装饰审美的顺序裁决。
- 9:16 未留安全区、直接裁切横版；扇面出现实体折扇、缺平面画布、缺品牌锚点或混入多张参考母版。
- 同文章角色未引用唯一母版、尺度漂移超过 ±10%，或未经 QA 就继续批量生成。

只交付通过 QA 的正式图、对应 prompt 和必要回执；没有图像工具、视觉 QA 不可用或证据不足时，明确标记“未验证 / BLOCKED”，不把候选图当正式图。
