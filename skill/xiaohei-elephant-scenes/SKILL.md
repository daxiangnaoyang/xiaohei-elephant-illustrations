# 小黑象 2.0 真实物品场景图

## 核心定位

把文章观点、用户处境、个人经历、项目过程和产品演化，转译成一个可传播的真实物品小现场：

```text
小黑象 + 真实物品 + 段落信息节点分层 + 物理动作 + 短中文标签 + 留白叙事
```

1.0 的 `xiaohei-elephant-illustrations` 更像白纸上的手绘解释图，适合拆观点、拆流程、拆方法。2.0 的 `xiaohei-elephant-scenes` 更像白色摄影棚里的真实物品现场，适合表达处境、压力、转折、项目故事和正文观点隐喻。

2.0 的正文图不是“主题名词配一张图”，而是“一个段落的一张视觉摘要”。每张图先从完整段落中提炼主旨、段落类型、处境/输入、独立信息节点、关键机制、结果/边界，再按段落复杂度选择 D1 / D2 / D3 密度档位，用真实物件、状态、空间层次、物理动作和短标签把这些节点连接起来。信息密度来自段落节点覆盖、层级、关系和可见结果，不来自物品堆、长文字或复杂信息图。

标准模式和选择“小黑象”品牌模式时，角色必须仍然是黑色小象：短象鼻、小耳朵、短腿、白点眼。真实物品可以摄影质感，但角色不能漂移成小黑人、黑色人形、火柴人、旧版小黑或普通黑色圆球；扇面内容分支若明确选择官方大象 logo，则执行该分支的官方资产规则。

- 每张标准图只表达一个段落级核心结论，但必须先理解完整段落，再把“处境/输入 -> 机制/主动作 -> 结果/判断/边界”编译成当前密度档位的可见结构，不能只摘主题名词。
- 标准图使用动态密度：D1 只用于单一判断，1 主 + 1 辅助、2-3 个标签、2-3 个节点；D2 是解释型段落默认档，1 主 + 2-3 辅助、4-5 个标签、3-4 个节点；D3 用于多步骤、多条件、多角色、对比、分支、反馈或明确边界，1 主/紧凑主组 + 3-5 个辅助物件或状态单元、5-7 个标签、4-6 个节点。每个单元都必须有段落语义职责，不合格的装饰物直接删掉。

- 根据段落关系选择一种简洁视觉语法：流程/因果用物理链，对比用前后分区，组成/层级用嵌套或堆叠，决策用闸门/筛选，闭环用一条弧形路径。允许少量手绘箭头、分隔线、圈选和勾选，但不能变成卡片网格、节点墙或 PPT 信息图。

- 不能确认的人名、品牌、数据、经历和案例，不画成事实；用概括性标签替代。不要虚构不存在的品牌、伪造 logo 或把 logo 改造成近似山寨标识。

## Core Flow

### 1. 判断模式

先判断用户要哪种输出：

- **标准模式**：16:9 正文配图，一个段落级真实物品小现场，一条主物理动作链，补足关键机制与结果/边界。
- **Cover 模式**：21:9 公众号封面/头图，深色科技感背景，一个小黑象 2.0 真实物品核心隐喻，标题区与主视觉分开。
- **9:16 视频封面分支**：9:16 竖版短视频封面，沿用 Cover 的一体成型文字和手机安全区；默认使用扇面内容视觉变体或用户已确认的其他真实物品隐喻，改为顶部安全区—中部平面内容画布—下部金句的竖向构图；不得直接裁切 21:9。
- **彩蛋长卷模式**：超横版真实物品故事线，5-8 个节点，适合项目复盘、个人经历、产品演化。

如果用户没有明确说“封面 / cover / 头图 / 长卷 / 彩蛋 / 时间线 / 复盘路径”，默认标准模式。

### 2. 提炼段落结构、处境和物理动作

不要只摘主题，也不要先堆物品；先读完整段落并编译信息结构：

- 这一段的一句话主旨或结论是什么？
- 读者面对的具体处境、输入问题或起始状态是什么？
- 这段属于哪种结构：单一判断、因果机制、流程步骤、对比转折、组成层级、决策筛选、反馈闭环还是案例复盘？
- 哪些独立信息节点不能互相替代：输入、机制、阶段、角色、条件、证据、结果或边界？先列出节点，再决定哪些用物件、状态、空间位置、动作、关系线或短标签承载。
- 最终结果、判断或边界是什么？能否用可触碰的物件状态表达？
- 这段最适合流程、因果、对比、组成、层级、闭环还是决策门中的哪一种视觉关系？
- 哪个主物理动作能把这些信息串起来？小黑象应该推、拉、挡、托、盖章、检查、修补、搬运、拧紧、拉绳还是守门？动作优先用象鼻完成，不给小黑象加人类手臂。
- 按节点数量与逻辑选择密度档位：D1 仅限单一判断；D2 是解释型段落默认档；D3 用于多步骤、多条件、多角色、对比、分支、反馈或 4+ 个不可合并节点。
- 按 D1 / D2 / D3 分别准备 2-3 / 4-5 / 5-7 个中文短标签，分别标记主旨、机制、结果、边界或关系；不能用标签替代画面节点。

如果用户提供了文章全文，按真实段落或小节边界拆图；如果只有标题或主题，没有完整段落内容，不要凭空补齐机制和结果，先把缺失信息标为“未获取”，或只输出待补充的 shot list，不直接声称已经完成段落级表达。

完成后，每张图必须有：

```text

原始段落 / 小节正文：
段落主旨 / 一句话结论：
读者处境：
输入/起始状态：
核心冲突句：
段落类型 / 结构：
独立信息节点（按段落事实列出）：
密度档位（D1 / D2 / D3）及选择依据：
必须看见的节点及视觉承载方式：

视觉关系类型：流程 / 因果 / 对比 / 组成 / 层级 / 闭环 / 决策门

画面 3 秒读懂句：
风险/避坑：
```

### 3. 标准图生成

每张图单独生成，不拼图。

如果同一篇文章有 2 张及以上标准图，必须先执行“文章批次角色锁”：

1. 只生成第 1 张候选图；通过四足、短象鼻、小耳朵、白点眼和 3%—5% 尺度 QA 后，冻结为本文章母版。
2. 将母版路径和实际高度占比记入 `prompts/xiaohei-character-lock.md`，模板见 `templates/article-character-lock.md`。
3. 后续每张单独生成时，始终把同一张母版传入 `referenced_image_paths`；不把第 2 张作为第 3 张的新参照，避免逐张漂移。
4. 每张生成后立即与母版并排 QA：同一画幅模式内，小黑象高度相对母版超过 ±10%，或头身、耳鼻、四足比例明显改变，直接重生。

21:9 cover、9:16 视频封面和 16:9 正文图的尺度目标不同：它们共用同一 IP 形体母版，但尺度只在相同模式内比较，不用 cover 的 4%—6% 去覆盖正文图的 3%—5%。

#### 封面运行时硬门禁（Cover Runtime）

封面字体漂移不是“再补一句 hand-drawn”就能解决的问题，必须按 `references/cover-typography-runtime-contract.md` 走状态机：

1. `PREPARE`：用 `scripts/make_cover_typography_reference.py` 从唯一的 `ZCOOLKuaiLe-Regular.woff2` 生成排版参考图；保存脚本输出的字体 SHA-256。参考图只允许作为视觉输入，不能成为图层。
2. `GENERATE_ONCE`：一次 `image_gen` 同时生成场景和所有白名单文字。输入只允许排版参考图和必要的 IP 母版；禁止把 `base`、`overlay`、透明文字层、上一张 Cover 或任何合成图作为文字修复输入。
3. `VISUAL_QA_PASS`：检查字形是否仍是圆润、轻松、略不规则的 ZCOOL KuaiLe 手写气质，并检查文字与场景的纹理、光影、透视是否一体。生成后必须创建 `templates/cover-typography-receipt.md` 的回执。
4. `DELIVER`：只有回执 `status: PASS`、`generation_passes: 1`、`visual_qa: PASS`、字体哈希匹配且无禁用中间产物时才可交付。QA 工具报错、超时、余额不足或无法读取图片时写 `BLOCKED`，不准降级成“看起来差不多”。

#### 生图通道：Codex 内置 image_gen 工具（首选）

**默认口径**

- 只有用户明确要求“生成 / 出图 / 做一张 / 做几张”时才进入生图；只要方案、模板或 shot list 时不直接生图。
- 当前 Codex 环境暴露内置 `image_gen` 时，默认用它逐张生成；不要求用户在仓库或 Skill 里额外填写 OpenAI API key。
- 当前环境没有生图工具时，只输出 prompt、QA 标准和交接说明，不假装已经生成图片。
- 外部 GitHub 用户如果不在 Codex 内置生图环境里运行，需要接入自己的图像生成通道；走 OpenAI Images API、FAL、智谱或第三方服务时，用他们自己的 key、余额和权限。
- 原生 ChatGPT / 自定义 GPT 可以复制 prompt 手动使用，但不能自动等同于本 Skill 运行时，也不能默认读取本机项目、创建 `06-配图方案.md` 或保存图片到指定目录。

**为什么优先用 Codex，而不是 Hermes 内置 image_generate 或 CogView？**
- Hermes 内置 `image_generate` 需要 FAL_KEY，且目前未配置
- 智谱 CogView-3-Flash 小黑象形态不准、中文标签无法清晰渲染，指令遵从度极差
- 智谱 CogView-3-Plus 余额不足时无备选
- Codex 登录态可用且暴露内置 `image_gen` 时，不需要在本仓库额外配置 OpenAI API key；当前小黑象形体、中文短标签和负面约束更适合用这一通道

**Codex 生成命令模板：**

```bash
# 单张生成（推荐，稳定性最好）
cd "<输出目录>" && codex exec --sandbox workspace-write --skip-git-repo-check --ephemeral \
  "用你的内置 image_gen 工具生成一张配图并保存到当前目录，文件名 <文件名.png>。Prompt: <英文提示词>"

# 多张批量生成
cd "<输出目录>" && codex exec --sandbox workspace-write --skip-git-repo-check --ephemeral \
  "用内置 image_gen 工具逐张生成以下配图，保存到当前目录：
  第1张，文件名 xx.png：Prompt: ...
  第2张，文件名 yy.png：Prompt: ..."
```

**注意事项：**
- `--sandbox workspace-write` 让 Codex 能写文件到工作目录
- `--skip-git-repo-check` 允许在非 git 目录执行
- `--ephemeral` 不保留 Codex session 文件
- Codex 内置 image_gen 默认保存到 `$CODEX_HOME/generated_images/`，需要 Codex 自己 move/copy 到工作目录
- GPT-image-1 每张约 30-60 秒，5 张批量约 8-10 分钟
- 生成后在 Hermes 内用 `codex exec -i "图片.png"` 做视觉 QA
- Cover 必须把视觉 QA 结果写入 `cover-typography-receipt.md`；如果 Hermes 的视觉适配器返回 400/429 或不可用，回执保持 `BLOCKED`，不得发送正式封面。

**Codex 生图 prompt 要点（英文，GPT-image-1 英文效果最好）：**
- 标准图先写尺度补偿块：`SCALE IS THE FIRST PRIORITY ... target only 1.5%-2.5% ... main real object at least 6x taller ... never enlarge the elephant.`，详见 `references/scale-calibration.md`。
- 标准图随后必须写段落级 `DENSITY CALIBRATION LOCK`：先完整理解段落，列出独立信息节点和段落类型，再选择 D1 / D2 / D3。D1 仅用于单一判断（1 主 + 1 辅助、2-3 标签、2-3 节点）；D2 是解释型段落默认档（1 主 + 2-3 辅助、4-5 标签、3-4 节点）；D3 用于多步骤、多条件、多角色、对比、分支、反馈或 4+ 个不可合并节点（1 主/紧凑主组 + 3-5 辅助物件或状态单元、5-7 标签、4-6 节点）。根据段落选择一种关系模式，并用一条主物理路径、箭头、闸门、分隔线或接触关系串联；D3 只允许一个分支或前后转折。不能把复杂段落压成 D1，也不能让标签替代画面节点。
- 必须包含 `references/xiaohei-elephant-ip-lock.md` 的 `Xiaohei Elephant 2.0 IP lock` 等价内容。
- 必须包含：`A tiny nimble solid BLACK elephant silhouette, SHORT TRUNK, SMALL ROUND EARS, FOUR SHORT ROUNDED ELEPHANT PEG LEGS under the body, WHITE DOT EYES, compact agile body, camera pulled far back, elephant height only 3%-5% of canvas height`
- 必须包含：`NO human figures, stick figures, robots, bears. Elephant is the ONLY character.`
- 必须包含：`No biped pose, no human legs, no stick legs, no knees, no feet, no shoes, no close-up, no low-angle hero shot, no bulky toy elephant, no heavy round statue.`
- 中文标签直接写中文字符，GPT-image-1 能正确渲染

**降级通道（Codex 不可用时）：**
1. CogView-3-Flash：`curl` 调用智谱 API（`https://open.bigmodel.cn/api/paas/v4/images/generations`，model=cogview-3-flash），质量差仅作后备
2. CogView-3-Plus：同上，需余额充足

#### 提示词必须包含

- 16:9 横版中文正文配图
- `#FFFFFF` 纯白或接近纯白摄影棚背景
- 按 D1 / D2 / D3 选择真实物品预算：1 主 + 1 辅助 / 1 主 + 2-3 辅助 / 1 主或紧凑主组 + 3-5 辅助物件或状态单元；每个单元必须对应段落节点并与其他节点有可读关系
- 如果主题明确涉及真实品牌 / 产品 / App，主物品可带官方品牌 logo、app icon 或产品标识；例如飞书用飞书标识，Codex / OpenAI 用 OpenAI 标识。logo 要小而准，贴在真实物品上，不做成品牌 KV。
- 小黑象参与主物理动作，并把段落的输入/机制/结果关系串起来
- 短象鼻、小耳朵、四足短圆桩腿、白点眼；禁止二足站姿、人形腿、火柴腿、鞋子脚掌
- 镜头后退，整体场景只占画面中等偏小区域；小黑象必须明显缩小，标准图高度约 3%-5% 画面高，黑色视觉体量约为此前测试图的 1/3，不超过主物品高度的 1/3；小黑象轻巧、灵活，不是笨重玩具或摆件
- 按密度档位使用 2-3 / 4-5 / 5-7 个中文手写短标签，分别标记主旨、机制、结果、边界或关系
- 一条清晰的段落级信息链：输入/处境 -> 机制/动作 -> 结果/边界；不能只画主题名词
- 少量蓝 / 黄 / 红 / 橙点缀
- 禁止小黑人、黑色人形、旧版小黑、火柴人、普通黑球、萌宠化、PPT 信息图、UI 截图、复杂架构图

真实物品要有自然光影和透视，但整体仍然轻、干净、有留白。画面第一眼应该像"一个真实、轻、怪、能读出段落关系的小现场"，不是商品摄影、PPT 大图或复杂道具堆。

### 3B. Cover 版生成

Cover 版是单独的一张图，不混入正文配图数量。

要求：

- 21:9 超横版公众号封面 / 头图。
- 参考 `../wechat-tech-cover-image` 的成熟封面规则：标题是第一视觉中心，深色科技背景、青橙对比、弱 HUD 网格、玻璃拟态卡片、发光连接线、科技手绘质感。
- 小黑象 2.0 融入主视觉：一个真实物品核心隐喻 + 小黑象用短象鼻参与动作。
- 如果 cover 主题明确涉及真实品牌 / 产品 / App，可在真实物品上使用对应官方 logo / app icon / 产品标识，作为识别锚点；logo 不应成为主标题或广告主视觉，也不暗示官方合作、授权或背书。
- 小黑象仍按 2.0 硬门槛：短象鼻、小耳朵、四足短圆桩腿、白点眼；禁止二足站姿、人形腿、火柴腿。
- Cover 里小黑象也只是小执行者，不是主视觉主体；高度约 4%-6% 画面高，黑色体量约为此前测试 cover 的 1/3，必须能看清但不能压过真实主物品。
- 生图前必须完成以下 Cover 内容单，不能只写“留出标题区”：

```text
封面主题：
主标题：用户原句优先；未提供时根据主题生成一个封面级标题
标题重点词：1-2 个，使用珊瑚红 #E8655A 突出
底部金句：一句短、锋利、有观点的话；用户原句优先，未提供时自动生成
封面级视觉隐喻：一个真实物品冲突
具体图解内容：起点物件/状态 -> 小黑象核心物理动作 -> 结果物件/状态
真实主物品：
小黑象动作：必须由短象鼻参与
画面 3 秒读懂句：
允许出现的文字：只列主标题、可选副标题、底部金句和必要短标签
```

- 主标题是第一视觉中心：标题区顶部居中，使用中文粗体大号手绘字；线条和主文字黑色，1-2 个重点词使用珊瑚红 `#E8655A`，辅助短标签使用暖灰 `#6B6B6B` 小字。深色底图必须提供暖白纸张标题区或等价浅色承载面，不能为了适配背景擅自改回白字科技黑体。
- **一体成型锁**：标题不是后期文字层，而是 Cover 的原生视觉主体。生成前可调用 `scripts/make_cover_typography_reference.py`，用全局品牌字体 `ZCOOL KuaiLe` 为本次主标题和金句生成排版参考图，并与场景 prompt 一起传给 `image_gen`；最终 Cover 仍必须由图像模型一次生成完整画面，不得把参考图直接贴到成图。
- **字体运行时锁**：排版参考图必须带 `TYPOGRAPHY_REFERENCE_ONLY` 元数据和字体 SHA-256；不得生成 `title-overlay-zcool.png` 或任何独立文字层。若模型返回标准科技黑体、几何尖角字或字体气质明显漂移，整张候选判定失败，禁止后期修字。
- 调用内置 `image_gen` 时，把本次排版参考图放入 `referenced_image_paths`，并在 prompt 中明确写 `reference is typography guidance only; render the final typography natively inside the scene`。这仍然只调用一次图像生成，不产生“底图生成 + 二次编辑”的额外 Token。
- 标题区加入少量手绘涂鸦点缀，如小星星、下划线、小箭头；保持充足留白和干净构图，不做装饰堆叠。
- 具体图解必须画出来，不能只写抽象概念：用一个真实主物品和一条清晰物理链路表达“输入/困境 -> 小黑象动作 -> 输出/转折”。最多 3 个连续状态，不做复杂流程图或节点墙。
- 标题区、主视觉区、底部金句区分开。底部金句字号明显小于主标题，不能抢焦点。
- 用户没有给标题或金句时，先根据主题补写再生成。主标题过长时先压缩文案或拆成两行，再一次生成；文字不稳时重写 prompt 或重新生成，不得切换到后期叠字。
- 生成后必须目视 QA：主标题应呈现粗重、略不规则的手绘笔画，并与背景共享纸张纹理、光影、透视和手绘装饰；若像后贴文字、网页/UI 字体或独立 PPT 标题卡，即使文字正确也判定失败并重做。
- 生成后必须完成字体运行回执；视觉 QA 不通过或不可用（包括 400、429、余额不足、超时）时，状态只能是 `BLOCKED`，不得交付候选图。

### 3C. 9:16 扇面内容型视频封面生成

当输入来自已确认的视频文稿，且项目采用本次的扇面内容视觉方向时，严格使用 `references/prompt-template.md` 的“9:16 扇面内容视觉分支”，不要临时改写成实体折扇或普通海报规则。

执行顺序：

1. 从已确认文稿提炼 `主题 → 一句话核心判断 → 主标题 → 底部金句`；文稿未确认时只输出待补充字段，不生成正式封面。
2. 从文稿确定一块平面扇面内容画布、一个主题色泼墨、2-4 个批注气泡、2-4 个卡通简笔图标和 1-2 个红色印章/印记；不复制参考图的原题字、印章、手或户外背景。
3. 明确写入“禁止实体折扇效果”：不出现扇片、扇骨、扇柄、折痕、手持关系、扇子图标或户外实拍背景。
4. 填写品牌锚点：默认 `BRAND_ANCHOR_MODE=小黑象`；如改用官方大象 logo，必须提供可核验的官方资产，并把 logo 绑定到平面版面的角标、标题旁或内容印记位置。两种模式只能选一个；红色印章不自动等同于品牌 logo。
5. 生成前将完整变量和最终 prompt 保存到项目归档的 `prompts/video-cover-fan-prompt.md`，并使用全局 `ZCOOL KuaiLe` 字体生成排版参考图；参考图只作为 `TYPOGRAPHY_REFERENCE_ONLY` 输入。
6. 只调用一次 `image_gen` 生成完整画面。封面必须同时包含平面内容画布、标题、泼墨、批注气泡、卡通简笔图标、红色印章、金句和品牌锚点；禁止无字底图、后期叠字、独立 logo 层和平台 UI。
7. 生成后按 `references/qa-checklist.md` 的 `9:16 Video Cover Branch` 与 `Fan Surface Variant` 检查，并创建 `cover-typography-receipt.md`。QA 不可用、返回 400/429/超时、出现实体折扇或品牌锚点缺失时，状态只能是 `BLOCKED`，不交付候选图。

输出：

- `04-封面.png`：9:16 扇面内容型视频封面，正式项目默认 1080×1920 或等比例竖版。
- `prompts/video-cover-fan-prompt.md`：本次实际变量值、最终 prompt 和 Allowed text 白名单。
- `cover-typography-receipt.md`：字体来源、单次生图、输入血缘与视觉 QA 回执。

### 4. 彩蛋长卷生成

彩蛋长卷用于个人经历、项目复盘、产品演化和成长路径。

要求：

- 超横版，约 `2.6:1` 到 `3:1`
- 高级近白背景
- 一条手绘曲线路径贯穿全图
- 5-8 个真实物品节点
- 每个节点都有小黑象参与动作
- 左侧是起点，右侧是当前结论或下一阶段
- 不用编号时间轴，不做 PPT 流程图
- 节点文案短，贴近物品，像手写注释

所有节点必须来自用户提供或可确认的事实。不能把别人的经历、项目和数据套进当前用户身上。

### 5. QA 和迭代

生成后按 `references/qa-checklist.md` 检查。以下任一情况不交付：

- 小黑象缺少短象鼻、小耳朵、短腿或白点眼
- 小黑象变成小黑人、旧小黑、火柴人、黑色人形或普通黑球
- 小黑象只有两条人形腿、火柴腿、膝盖、脚掌、鞋子，或变成二足站姿
- 小黑象变成笨重圆胖玩具、摆件、商品模型或近距离角色特写
- 真实物品太多，像素材拼贴；或只画了主题名词，没有机制、结果或边界
- 解释型段落被压成 D1，或不同复杂度的段落全部使用相同的“主物品 + 一个点缀”密度
- shot list 列出的独立信息节点没有落实到物件、状态、空间层次、动作、关系线或短标签，机制和结果被合并成一个泛化主题物件
- 主物品过大，像商品图
- 小黑象只是站在旁边，没有承担动作
- 同一文章的同模式多图中，小黑象高度相对母版漂移超过 ±10%，或形体明显忽胖忽瘦
- 标签太多、错字明显或像标题；或标签没有按 D1 / D2 / D3 分别对应信息节点、关系和边界
- 物件之间没有关系，画面像孤立物品排队，无法看出输入 -> 机制 -> 结果
- 画面像 PPT、UI 截图、复杂架构图、商业海报
- Cover 出现 `title-overlay-zcool.png`、透明文字 PNG、`*-base.*`、`*text-layer*`、`*composite*` 或 `*merged*`，或回执缺失/QA 不可用
- 扇面内容分支出现实体折扇、扇片、扇骨、扇柄、折痕、手持关系、扇子图标或户外实拍背景
- 扇面内容分支没有平面内容画布、主标题、主题色泼墨、批注气泡、卡通简笔图标或红色印章中的关键元素，或出现参考图原题字/印章的直接复制
- 扇面内容分支缺少品牌锚点，或“小黑象/官方大象 logo”同时出现、漂浮、伪造或抢过主标题
- 扇面内容分支没有手机上下安全区，气泡框遮住主标题/金句，或图标、印章和批注堆成信息图
- 需要长解释才看懂

第一张生成图只算候选图。未过 QA 就重写提示词或重生成。

## Quality Gates

- 2.0 必须出现真实物品和明确物理动作。
- 2.0 标准图及选择“小黑象”品牌模式时，小黑象必须是小象，不得回退旧小黑。
