# 统一小黑象推送结构

> 用途：把公众号终稿后的“小黑象正文配图 / 小黑象 2.0 场景图 / 后续飞书排版接棒”固定成一套可复用交付结构。

## 资产边界

本文件属于 Skill 本体：它定义触发条件、固定产物、字段顺序、路由规则和 QA。执行任务时可以直接引用。

示例素材只放在 `examples/`，只能作为结构样例和脱敏参考，不能当作当前文章事实。

空白模板放在 `templates/`，执行时复制到文章项目目录或交接文档中填写。

## 触发条件

满足任一条件时触发本结构：

- 用户说“统一小黑象推送模板 / 小黑象推送模板 / 小黑象推送结构”。
- 公众号文章已有稳定终稿，需要继续做正文配图、图片归档和排版交接。
- 用户要求“小黑象配图后续怎么推送 / 怎么交给 Hermes / 怎么接飞书排版”。
- 用户要求为文章项目生成 `06-配图方案.md`、配图 shot list、生成记录和归档路径。

不触发：

- 文章还在初稿或改稿阶段。
- 用户只要单张概念图，不需要文章级交接结构。
- 用户明确不要配图或不要排版交接。

## 固定推送链路

```text
读取 05-终稿.md 或用户确认的正文
-> 判断使用 1.0 手绘解释图还是 2.0 真实物品场景图
-> 判断生图通道：Codex 内置 image_gen / 仅输出 prompt / 外部图像 API
-> 创建统一小黑象推送单
-> 产出 06-配图方案.md
-> 逐张生成或登记待生成图片
-> 图片与 prompt 归档到 /Users/dx/Hermes-agent/21-配图空间/<文章或项目名>/
-> 在排版前 Markdown 中插入图片引用
-> 交接 feishu-formatting-wechat-article 或后续排版流程
```

## 1.0 / 2.0 路由

默认用 `xiaohei-elephant-illustrations`：

- 用户只说“小黑象配图 / 小黑象正文配图 / 白底手绘 / 文章插图”。
- 需要表达认知判断、工具选型、提示词返工、信息过载、AI 输出验收、知识沉淀。
- 输出 16:9 纯白背景、黑色手绘线稿、低科技物理隐喻。

转交 `xiaohei-elephant-scenes`：

- 用户明确说“小黑象 2.0 / 真实物品 / 真实物件 / 小现场 / 场景图 / 彩蛋长卷”。
- 需要表达项目复盘、个人经历、产品演化或真实物品隐喻。
- 输出 16:9 真实物品小现场，或 2.6:1 到 3:1 彩蛋长卷。

禁止回退：

- 任何“小黑象”请求都不得回退到旧 `xiaohei-scenes` 的人形小黑。
- 如果画面没有短象鼻、小耳朵、短腿、白点眼，判失败。

## 执行规则

1. 未确认终稿时，只能记录“配图需求”或输出初版 shot list，不生成正式图。
2. 标准公众号文章默认 4-6 张正文配图；短文 1-3 张；长教程或长复盘最多 8 张。
3. 先写 `06-配图方案.md`，再逐张出图。
4. 每张图都要有母版/质量锚点、至少 3 个变异点和 3 秒读懂句。
5. 生成图只算候选，QA 通过后才进入排版。
6. 公众号正文配图与封面图分开处理；封面图按 21:9 封面模板，不混进正文图数量。
7. 交接时必须说明哪些内容已完成、哪些只是待生成计划。
8. 生图通道说明必须引用 `references/generation-runtime-notes.md` 的口径：仓库不是托管生图服务；Codex 内置 `image_gen` 场景通常不需要额外 OpenAI API key；外部 API 需要用户自己的 key；原生 GPT 只能复制 prompt 手动使用，不能自动执行本地 Skill 文件流。
