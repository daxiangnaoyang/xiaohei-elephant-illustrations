# 文章配图策略

## 目标

小黑象正文配图不是给每段文章补装饰，而是把文章里的认知动作画出来。

优先画这些位置：

- 开头痛点：读者最容易代入的处境
- 核心判断：文章真正想让读者记住的一句话
- 流程断点：从输入到输出之间最容易卡住的地方
- 方法转折：从“以为该这么做”到“其实要这么做”
- 验收节点：AI 输出、工具结果、项目交付需要人判断的地方
- 收束建议：读者下一步可以立刻做的动作

不要画这些位置：

- 纯过渡段
- 已经很直白的定义解释
- 数据或事实未确认的案例
- 只适合表格、代码块、截图的内容
- 一段里同时塞了多个观点的复杂段落

## Shot List 输出格式

```text
位置：放在第几段/哪个小标题后
主题：短标题，不上图
核心意思：这张图要让读者记住什么
构图模式：Workflow / 系统局部 / 前后对比 / 角色状态 / 概念隐喻 / 方法分层 / 地图路线 / 小漫画分镜
核心物理动作：卡住 / 分拣 / 卷起 / 拆箱 / 盖章 / 修补 / 搬运 / 压实 / 喷洗 / 守门
小黑象动作：具体正在做什么
关键物件：只列 1 个主物件或 1 组紧凑物件
中文短标签：2-4 个短词
成图理由：为什么这里值得画
风险/避坑：最容易跑偏成什么
```

## 数量规则

- 短文：1-3 张
- 标准公众号文章：4-6 张
- 长教程或长复盘：6-8 张
- 不建议超过 8 张；超过后会变成画册而不是正文配图系统

## 排布节奏

一篇文章的配图节奏建议：

1. 第一张：读者处境图，解决代入
2. 中间 2-4 张：流程、方法、断点、对比
3. 最后一张：行动或验收图，解决收束

不要连续三张都画同一种动作。例如连续分拣、连续搬运、连续盖章都会显得重复。

## 事实约束

涉及用户经历、品牌、项目、数据、案例时，只画用户明确提供的部分。不能确认的内容用“工具”“素材”“项目”“输出”“证据”等泛化标签替代。
